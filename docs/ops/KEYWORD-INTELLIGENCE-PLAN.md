## 0. 결론 (TL;DR)

1. **2주 내 숫자가 나오는 조합은 시기성×롱테일뿐.** 발행 배분 = **롱테일 60% / 세부 30% / 대형 10%**(대형은 신규 글 금지 — hub·갱신만). 마감 D-14·지급일 ±3일·확정 발표 24h는 계층 무관 1순위 오버라이드.
2. **오늘 최속 액션은 신규 발행이 아니라 갱신·회수다**: ① 청년미래적금 8건 확정수치 갱신(6/22~7/3 모집·5부제·은행별 금리 확정 보도됨, D-10) ② trendingTerm 누락 15편 소급 + '복지급여' byTerm 시드로 hub 2개 즉시 회수(발행 0건).
3. **수집 파이프라인은 크롤링이 아니라 공식 API로 짠다**: 운영자 참고안의 숏텐츠·아하 크롤링은 검증 결과 **기각**(약관·robots 금지 실측). 대체 = 기존 NAVER_CLIENT_ID 그대로 쓰는 **지식iN 검색 API(kin.json, 일 25,000회)** + 데이터랩 검색어트렌드(권한 추가 1클릭).

## 2. 키워드 4계층 체계

| 계층 | 정의 | 예 | 받는 표면 | 첫 유입까지 |
|---|---|---|---|---|
| 대형(head) | 제도명 단독 | 청년미래적금 | `/subsidies/[id]/`(공식명)·`/issues/topics/[term]/`(트렌딩)·`/topics/`(에버그린) | 수개월+ — 신규 글 금지, hub로만 |
| 세부(mid) | 제도명+의도 1개 | 청년미래적금 은행별 금리 | `/issues/` spoke (글당 의도 1개) | 3주~2개월 (추정) |
| 롱테일 | 질문 문장형 | 실업급여 받으면서 알바하면 걸리나요 | spoke의 title·H2·FAQ가 흡수 (단독 글은 thin 위험 시 금지) | 색인 후 3일~2주 (추정) — AI 브리핑은 Top10 밖 문서도 49.3% 인용 |
| 시기성 | 마감 D-N·지급일·확정 발표 | 청년미래적금 5부제 내 신청일 | `deadline-imminent-weekly` spoke | 24~72h — 색인 속도가 유일한 병목 |

**배분 공식**: 롱테일 60 / 세부 30 / 대형 10(갱신·hub 보강만).
**시기성 오버라이드**: ① 마감 D-14·지급일 ±3일·발표 24h → 당일 1순위 강제 ② title은 반드시 롱테일형(head 단독 금지) ③ 발행 즉시 색인 3종(IndexNow·GSC·네이버 수집요청) ④ 종료 후 hub "지난 회차"로 귀속.
**카니발 계층 규칙**: head 단독 title은 한 표면만 점유 / 의도 토큰(신청·계산·비교·마감)은 클러스터 내 1글 독점 / hub·pillar는 집계자(자체 롱테일 본문 금지).

## 3. 키워드 레이더 파이프라인 (합법 스택 확정판)

```
sources (Promise.allSettled, 실패 격리)
├─ [P0] naver-kin.mjs        지식iN 검색 API kin.json — 시드사전("지원금·수당·바우처·장려금"×접미사) × sort=date 신규 질문
├─ [P0] history-baseline     기존 _history.json 뉴스 트렌딩 카운트 참조 (재수집 X)
├─ [P1] naver-datalab.mjs    데이터랩 검색어트렌드 — 후보 키워드 상대수요 검증 (개발자센터 권한 추가 1회, 일 1,000회)
├─ [옵션] naver-autocomplete  온디맨드 전용(발행 직전 --dry-run) — robots 리스크 인지하 소량, 차단 징후 시 제거
└─ [기각] 숏텐츠·아하 크롤링 — 금지선
   ↓ normalize(clean 재사용) → 도메인필터(접미사사전+matchSubsidies≥1) → 스팸필터(보험·대출·폰테크 사전)
   ↓ score = 지식iN 신규질문 증가율×1.5 + 뉴스 트렌딩×1.0 + 데이터랩 상대지수×1.0
   ↓ src/data/keyword-radar.json (30일 롤링·스냅샷당 top30·500KB 가드)
   ↓ 소비: keyword-scout 입력 1순위 / /today PHASE 2 / /traffic
```

- **cron**: `.github/workflows/keyword-radar.yml` — KST 06:17·11:17·16:17·21:17 (분 오프셋·sync-issues race 회피), diff 게이트, `[skip ci]`, 배포 스텝 없음, `chore(radar)` prefix(scout의 git log 중복체크에서 제외).
- **재사용**: sync-issues.mjs의 env 로더·clean()·필터사전·matchSubsidies를 `scripts/keyword-radar/lib/`로 추출, sync-issues도 같은 모듈 import (사전 단일화).
- **구현 로드맵**: P0(1일) = kin.json 수집기+파이프라인 관통+워크플로 / P1(1주) = 데이터랩·delta 스코어·scout 통합·lint 가드 / P2(외부 의존) = 검색광고 RelKwdStat(키 3종 필요 → backlog-external).
