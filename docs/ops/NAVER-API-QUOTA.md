## 3. 집계 방식

`scripts/lib/api-quota.mjs`가 호출 지점마다 `countCall(group, name)`으로 센다.
실행 끝에 `formatUsage()`가 콘솔에 찍고, 레이더는 `keyword-radar.json`의 `apiUsage`에도 남긴다.

- 실제 누적이 아니라 **"이 스케줄대로 돌면 얼마를 쓰는가"의 산출값**이다.
  실누적은 Ncloud 콘솔에서 본다.
- cron을 바꾸면 각 스크립트의 `RUNS_PER_DAY` 상수도 같이 바꿔야 추정이 맞는다.
- 한 실행이 500회를 넘으면 호출 루프 버그로 보고 즉시 예외를 던진다(`RUN_CEILING`).

## 4. 여유로 할 수 있는 것 (미실행 — 운영자 판단)

| 안 | 변경 | 추가 호출 | 변경 후 일 사용률 |
|---|---|---|---|
| 시장조사 확대 | `MARKET_TOP` 15 → 60 | +135/회 | 0.9% → 3.1% |
| 데이터랩 확대 | `DATALAB_TOP` 20 → 40 | +4/회 | 랩 월 2.4% → 4.3% |
| 연령 프로파일 확대 | `DEMO_TOP` 10 → 30 | +12/회 | 랩 월 4.3% → 7.2% |

**웹문서 API(`/search/v1/webkr`)가 한도에 포함돼 있다.** 지금 `naver-serp-scout`는
통합검색 HTML을 직접 받아 파싱하는데, 웹문서 API를 쓰면 "이 쿼리에 어떤 외부 문서가
잡혀 있는지"를 정식 경로로 받을 수 있다. 다만 API 결과와 통합검색 SERP 노출은
같지 않으므로 **SERP 실측을 대체하지는 못한다** — 후보를 넓게 거르는 1차 필터로만 쓸 것.

## 5. 키

- HUB(Ncloud): `NCP_API_KEY_ID` / `NCP_API_KEY` → 헤더 `X-NCP-APIGW-API-KEY-ID` / `X-NCP-APIGW-API-KEY`
- 레거시 오픈API: `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET`
- **둘 다 GitHub Secrets에만 둔다.** NCP 키가 있으면 자동으로 HUB를 쓰고, 없으면 레거시로 떨어진다.
  전환·롤백 모두 시크릿만 넣고 빼면 된다. 코드 변경 불필요.
