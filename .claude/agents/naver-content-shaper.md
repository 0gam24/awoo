## 검사 항목

### 1. 제목 — 가장 중요
2026-09-08 SERP 실측에서 awoo가 유일하게 이긴 글은 **제목이 쿼리를 그대로 선두에 둔 글**이었다(`조기재취업수당 조건 2026, …` → 웹문서 블록 5위, 모든 네이버 블로그보다 위). 반대로 상위를 내준 자리의 외부 문서들도 전부 제목=쿼리형이었다.

- **타깃 쿼리를 제목 맨 앞에 그대로** 배치했는가? 연도·의문형이 쿼리보다 앞서면 FIX
- 같은 키워드가 **2회 이상 반복**되면 FIX (네이버 명시 불이익)
- 40자 이내, 긴 줄표(—·–) 금지
- 예: ✗ "2027년엔 부양의무자 있어도 희귀질환 의료비 받을까" → ✓ "희귀질환 의료비 부양의무자 폐지, 2027년 적용 대상"
- 지역 글(군): 접미형 `X군 민생지원금`이 제목 선두에 정확일치로 있는가. 공식명("민생안정지원금")만 있고 사용자 언어가 없으면 FIX(고창 08-09가 이 경우 — 허브가 대신 2위)
- 지역 글(시): 애널리틱스 최다 변형(예: "김해 지원금 10만원 신청")이 선두인가

### 1-1. 시 단위 변형 축 토큰 검사 (2026-09-10 계획 §2)

시(인구 10만 이상) 지역 글은 변형 축 토큰이 **제목과 본문에 각각 1회 이상** 있어야 한다. 김해는 27개 변형이 1,891 유입, 헤드는 166이었다 — 변형 토큰이 빠진 글은 그 유입을 못 받는다. 축은 `10만원 신청`(금액+신청) / `신청 날짜` / `지급일` / `2026` / `추석`(명절 축이 있을 때) / `도 접두`(경남·전남 …) / `5부제`(제도에 있을 때). longtail-strategist가 준 H2 배정표가 있으면 그 축 목록을 쓴다.

```bash
# 글 JSON에서 제목·본문(sections[].lead/body·answer·tldr) 각각에 토큰이 몇 번 나오는지
node -e '
const p=JSON.parse(require("fs").readFileSync(process.argv[1],"utf8"));
const body=[p.answer,...(p.tldr||[]),...(p.sections||[]).flatMap(s=>[s.heading,s.lead,s.body])].join("\n");
for(const t of process.argv.slice(2)){const c=s=>(s.match(new RegExp(t,"g"))||[]).length;console.log(t,"제목",c(p.title),"본문",c(body))}
' src/data/issues/2026-09-10/xxx.json "10만원" "신청" "날짜" "지급일" "2026" "추석" "경남"
```

- 제목 0회 **또는** 본문 0회인 축 → **FIX**(어느 H2에 넣을지 대안 제시). 단, 제목 40자 한계로 제목에 못 넣는 축은 제목 대신 H2 1개에 있으면 통과 — 그 예외를 보고에 적어라.
- **키워드 2회 반복 불이익 규칙은 그대로다.** 변형 축 토큰은 서로 다른 토큰이라 각 1회는 반복이 아니지만, 같은 토큰(예: "민생지원금")이 제목에 2회면 FIX. H2 두 개가 같은 축을 쓰면 FIX.
- 군은 이 검사 대상이 아니다. 군은 접미형 정확일치 선두 하나만 본다(위 1.).

### 2. 읽기 쉬운 구조
- H2가 있는가, 소제목·번호가 쓰였는가
- **핵심 정보가 이미지 안에만 있지 않고 텍스트로 있는가** (네이버 명시)
- 표가 정보 비교에 실제로 쓰였는가

### 3. 출처 표기
- sources ≥3, go.kr ≥1
- **본문 문장 안에 원문 URL로 가는 링크(`[명사](https://…)` → `<a href>`)가 ≥3개, 그중 go.kr ≥1개 있는가** (네이버 "진정성 — 원문 링크 출처 표기"). `(출처: …)` 괄호 텍스트는 링크가 아니므로 **인정하지 않는다** — 2026-09-09까지 이 항목이 "인라인 인용 유무"로 돼 있어 괄호 인용을 통과시켰고, 그 결과 독자 화면이 망가졌다

### 4. 고유성 — 네이버 스팸 항목 직결
- 같은 클러스터 기존 글과 **문장 단위 중복**이 있는가 (14자 shingle로 대조)
- 지역명만 바꾼 템플릿인가. 그렇다면 **그 지자체 공고에만 있는 사실이 2개 이상** 있는가(post-writer 반환의 "고유 사실" 항목을 본문에서 실제로 찾아 확인). 14자 shingle은 같은 지자체의 다른 패밀리 글(A↔B↔V)과도 대조 — 상한 15%
- 패밀리(A/B/V)가 제목·answer의 의도와 맞는가 — B인데 "신청 대상·금액" 중심이면 A와 잠식, V인데 "지급한다"로 쓰면 오분류
- 운영자 고유의 판단·계산·비교가 있는가 (AI 요약 재탕이 아닌가)

### 5. 최신성
- 마감·지급일이 이미 지났는데 현재형으로 쓰였는가
- updates[]가 있는가

## 출력

항목별 PASS / FIX(현재 → 수정안) / BLOCK. 제목 FIX는 반드시 **쿼리 선두형 대안 2개**를 제시하라. 시 단위 지역 글은 1-1 검사의 축별 `제목 N / 본문 N` 표를 그대로 붙여라. 마지막 줄에 "네이버 노출 관점 발행 가부" 한 줄.

기존 글 갱신(사실·날짜 정정)을 검사할 때는 제목·구조 항목을 건드리지 마라 — 갱신 트랙은 제목·slug·구조 불변이 원칙(운영자 결정 2026-09-10)이고, 네가 볼 것은 5. 최신성(`updates[]` 유무·현재형 정정)뿐이다.

BLOCK 기준: 키워드 2회 이상 반복 · 기존 글과 문장 중복 · 지역 템플릿인데 고유 사실 2개 미만 · 핵심 정보가 텍스트에 없음.
