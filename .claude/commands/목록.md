# /목록 — 오늘 글감 목록

운영자가 **"목록"**, `/목록`, "글감 보여줘", "오늘 뭐 쓸까"라고 하면 실행한다. 대시보드 전체가 아니라 **글감 목록 하나**만 빠르게 보여주는 명령이다.

## 순서

1. **최신화.** 봇이 커밋한 큐·순위를 가져오고, **다음에 크게 뜰 주제**를 재고, 목록을 다시 만든다. 로컬에 커밋 안 한 변경이 있으면 pull을 건너뛰고 그 사실만 보고한다.
   ```bash
   git pull --ff-only origin main && node scripts/next-wave.mjs --if-stale && node scripts/ops-widget.mjs --limit=10
   ```
   큐가 오늘 것이 아니면(`docs/ops/pipeline-queue.json`의 `meta.today` ≠ 오늘 KST) 먼저 `node scripts/keyword-pipeline.mjs --serp`로 다시 만든다.
   `next-wave.mjs`는 매일 아침 봇(keyword-pipeline 워크플로)도 돌린다. `--if-stale`은 오늘 결과가 이미 있으면 API를 부르지 않는다. 실패해도 목록은 띄운다(그 칸만 빠진다).
2. **띄우기.** 위 출력(HTML 조각)을 그대로 `mcp__visualize__show_widget`(title `today_post_picks`)으로 채팅에 띄운다. 먼저 `mcp__visualize__read_me` modules `["interactive"]`를 호출한다.
3. **수량 한 줄.** 위젯 위나 아래에 오늘 발행 현황을 한 줄로 쓴다. 아래 명령의 출력을 그대로 쓴다.
   ```bash
   node scripts/ops-widget.mjs --count
   ```
   형식: `오늘 발행 N건(자동 1 · 수동 N) · 어제 N건`. 0건이면 그 사실과 원인(0400 PR 미머지·CI 실패 등)을 확인해 함께 적는다.
4. **다음 물결 한두 줄.** 위젯 아래 "다음에 크게 뜰 주제" 칸을 쉬운 말로 한두 줄 요약한다 — 무엇이 뜨는 중·곧 뜸인지, 무엇이 꺾여서 새 글을 멈출지. 운영자 지시(2026-10-02): "빈틈 키워드 매일 목록 요청하면 다음에 크게 뜰 주제도 함께 알아와". 근거는 [[revenue-decline-2026-10]] — 민생·추석 물결이 끝나자 수익이 꺾였고, 반값여행은 이미 컸는데 손으로 늦게 찾았다.
5. **끝.** 순위·트래픽·갱신 같은 다른 카드는 보여주지 않는다. 그건 `/dashboard`의 몫이다.

## 다음에 크게 뜰 주제 칸 읽는 법

`scripts/next-wave.mjs` → `docs/ops/next-wave.json`. 검색어 하나가 아니라 **주제 묶음**(이름 + 이름 신청 + 기사에 같이 나온 지역 변형)을 56일 일별로 잰다. 눈금은 실업급여 28일 평균 = 100.

| 표시 | 뜻 |
|---|---|
| 지금 뜨는 중 | 최근 7일이 직전 3주의 1.4배 이상이고 크기 8 이상 |
| 곧 뜸 | 작년 이맘때 한두 달 뒤 1.5배 이상 커졌고(작년에도 있던 이름만), 지금도 크게 꺾이지 않음 |
| 커지는 중 | 1.2배 이상이고 크기 2 이상, 또는 뉴스에 처음 보인 지 3일 이내 |
| 큰데 우리 글 적음 | 크기 30 이상인데 우리 글 2개 이하 |
| 꺾이는 중(한 줄) | 0.6배 이하 — 새 글 대신 기존 글 갱신만 |

후보 출처: 뉴스 검색 API 최근 제목(정책·혜택 이름 + 같이 나온 지역 수), 고정 감시 목록 `docs/ops/next-wave-seeds.json`, 레이더 신생 키워드. "곧 뜸"·"큰데 글 적음"은 감시 목록이거나 기사에 지역이 3곳 이상 나온 묶음만 — 뉴스 잡음(카드사 상품·관세청 유니패스)을 거른다.

## 버튼 동작

- **발행 지시 ↗** → `발행: <쿼리> — 대시보드 지시…` 가 채팅에 입력된다. `/post`의 "대시보드 버튼 지시" 절차로 결재 질문 없이 작성·검증·발행. (버튼 문구는 슬래시로 시작하지 않는다 — [[widget-button-no-slash-prefix]])
- **선점 ↗** (다음 물결 칸) → `선점: "<주제>" — 다음 물결…`. 묶음을 지역·세부 검색어로 쪼개 빈틈 목록에 넣는다:
  ```bash
  node scripts/wave-split.mjs --term="<주제>"
  ```
  지역 변형(기사에 같이 나온 지역) + 세부 변형(신청·대상·기간·사용처·환급… + 지식iN 질문 제목에서 주제 뒤에 자주 붙는 말)을 만들고, 검색량을 재고(지역 0.3·세부 0.5 이상), 상위 8건을 검색 결과 실측해 **자리가 열린 것만** `빈틈:<검색어>` 항목으로 큐에 넣는다(21일 유지, 노출 가능성 점수는 파이프라인과 같은 `scripts/lib/exposure.mjs`). 넣은 것·뺀 이유를 쉬운 말로 보고하고 1~3단계를 다시 해 목록을 보여준다. 큐 변경은 커밋·push한다(`chore(ops): 다음 물결 선점 — <주제> 빈틈 N건`). **선점은 글감을 목록에 올리는 것까지다 — 글은 운영자가 그 항목의 발행 지시를 눌러야 쓴다.**
- **보류** (다음 물결 칸) → `보류: "<주제>" 물결 …`. `docs/ops/next-wave-seeds.json`의 `ignore`에 그 이름을 넣고(감시 목록 `seeds`에 있으면 거기서 뺀다) 커밋한다. 다음 측정부터 재지도 보여주지도 않는다.
- **보류** → 큐 status를 `hold`로.
- **실측 ↗** → `실측: "<쿼리>" …`. `node scripts/keyword-pipeline.mjs --serp` 로 다시 재고 목록을 갱신해 보여준다.
- **[첫 화면] [한 번 스크롤] [그 아래]** (상위 5건) → `눈확인: "<쿼리>" = <값> …`. 운영자가 네이버에서 그 검색어를 직접 보고, **웹문서 묶음이 화면 어디쯤에 있는지** 누른다. 2026-09-15부터 이 값이 종전 `webDocOffset`(≥30% 신규 금지)을 대신한다 — 공식 API로는 잴 수 없다. 받으면:
  ```bash
  node scripts/eye-offset.mjs --query="<쿼리>" --value="<첫 화면|한 번 스크롤|그 아래>"
  node scripts/keyword-pipeline.mjs --serp-replay   # 오늘 실측분 재사용 — 추가 호출 없음
  ```
  그다음 1~3단계를 다시 해 목록을 갱신한다. `그 아래`면 그 후보는 닫힘으로 빠진다. 기록은 `docs/ops/eye-offset.json`(7일 지나면 무시)이고, **Claude가 네이버 화면을 대신 보지 않는다.**

## 정렬

노출 가능성(exposure) 높은 순. 점수 규칙은 `scripts/keyword-pipeline.mjs`의 `exposureOf()`와 `docs/ops/DAILY-KEYWORDS.md` "읽는 법"에 있다. 실측 전 항목은 아래 "실측 대기"로 모인다.

## 금지

- 새 브라우저 창을 열지 않는다. 대시보드 전체를 다시 그리지 않는다(그건 `/dashboard`).
- 발행은 운영자가 버튼을 누를 때만. 목록을 보여주면서 먼저 쓰지 않는다.
