# /naver-daily — 측정하고, 고치고, 다시 쏜다

목표는 하나다. **네이버 통합검색 상단이 awoo 포스팅으로 채워지는 것.**

이 명령의 다른 명령과의 차이는 **1단계**다. 다른 파이프라인은 "쓰기 전"만 다루는데, 여기는 **지난 회차 결과를 먼저 재고** 그 결과로 오늘의 각도를 정한다. 측정 없이 반복하면 같은 실수를 무한히 반복한다.

인자: `$ARGUMENTS` (키워드 지정 시 발굴 단계를 건너뛴다)

## 전제 — 이미 확인된 사실 (다시 조사하지 마라)

2026-09-08~09 1차 출처·SERP·API 실측 결과다. 근거는 `docs/ops/NAVER-TOP-EXPOSURE.md`. **판정 규칙의 원본은 `docs/ops/KEYWORD-PLAN-2026-09-10.md`(계획 v3)다** — 이 문서와 어긋나면 계획이 이긴다.

- awoo는 이미 네이버 웹문서 **5위**에 올라 있다(`실업급여 조기재취업수당 조건`, 모든 네이버 블로그보다 위). 네이버가 AI 출처 정보까지 붙였다 → **도메인 신뢰는 확보돼 있다.**
- 색인은 문제없다. 신규 글이 **발행 당일 색인**된다. **병목은 랭킹이다.**
- 상위 외부 문서는 awoo보다 짧고 표도 구조화 데이터도 적었다. **이긴 유일한 공통점은 제목이 검색 쿼리 그 자체**였다.
- SERP 133항목 중 네이버 UGC 55% / go.kr 20% / 외부 웹 8%. **외부가 들어간 자리를 고르는 것이 승부다.**
- API 한도 여유는 검색 월 75만회, 데이터랩 월 4.8만회. 조사 폭은 이미 넓혀 뒀다(`docs/ops/NAVER-API-QUOTA.md`).
- **2026-09-10 실유입 교정**: 애널리틱스 9/2~9/8 상위 160 검색어 유입의 **81%가 지자체 민생지원금(지역 61% + 롤업 20%)**. 데이터랩 헤드값과 실유입의 상관은 0.14 — **검색량은 게이트가 아니라 정렬 지표**다. 발행 트리거는 "공고·가결로 방금 열린 SERP"다.
- **운영자 결정(2026-09-10)**: ① 기존 글은 틀린 정보·바뀐 날짜만 고친다(`updates[]`·`dateModified`·표 행·사실 정정. 제목·slug·구조·전면 재작성 금지) ② 0400 자동 발행은 매일 1건 그대로, 이 루프가 대체하지 않는다 ③ **이 루프는 후보를 보고하고, 발행은 운영자 지시로만 한다.**

## 실행 순서

### 1. 성적 측정 (naver-rank-tracker spawn) — 건너뛰지 마라

어제까지 발행분이 실제로 몇 위인지 잰다. 산출은 셋이다.

- **올랐다** → 통한 요인을 오늘 글에 복제
- **못 올라갔다** → 교정안(제목 대안·보강 섹션)
- **버려라** → T2 쿼리에서 `openSlots 0`(옛 `externalCount 0`)이 반복되면 타깃에서 제외. 지역 쿼리의 `rank: null`은 버리지 말고 `aboveIsWholeBlock`·개시일 언론 벽(같은 제목 언론 ≥3)으로 원인을 먼저 가른다 — 4위 이하·미노출 지역 쿼리는 패밀리B 트리거다

여기서 나온 **"다음 글에 반영할 규칙"** 을 5단계 작성자에게 그대로 넘긴다(4단계 운영자 보고에도 "도출한 교정"으로 싣는다).

### 2. 후보 발굴 (emerging-keyword-hunter + cluster-auditor 병렬 spawn)

**물결 감지가 맨 앞이다**(계획 §3). 신호 1개면 후보, 2개면 확정. 입력은 다섯이다.

| 입력 | 어디서 | 무엇을 본다 |
|---|---|---|
| 실유입 검색어 | `src/data/analytics/*.json` (주 1회 적재) | 신규 지역명, 자사 없거나 4위 이하인 지역 쿼리(→ 패밀리B 트리거), 접미형("X군 민생지원금") 유입 |
| 레이더 `born` | `node scripts/keyword-radar.mjs --dry-run` 후보의 `born`·`signals.volume{recent7,trend,zeroDays,firstNonZero}` | 창 안에서 방금 생긴 키워드. `born`이면 검색량 문턱 없이 후보 |
| 가결 표 | 조례·추경 가결 WebSearch 일 1회, 강릉 `gncl.go.kr:8080/assembly/bill.do` curl, 계획 §5 표 | 가결·공고된 지자체와 개시일 → T1 후보 = 지자체 × 패밀리 |
| 언론 롤업 표 | 언론사 "지자체별 민생지원금 현황" 기사 표 diff 주 2회 | 가장 싼 검사. 새로 등장한 지자체 = 후보 |
| 접미형 일별 값 | `node scripts/keyword-volume.mjs --region <지역> --json` (`regionSum7`·`recentRelative`·`measured`) | 7일 내 2배면 신호. `measured:false`는 무응답이지 0이 아니다 |

- **emerging-keyword-hunter** — 위 입력에서 후보를 낸다. 비지역(T2) 후보는 `keyword-radar.json`의 `niche[]`·기회도(`opportunity`)를 그대로 쓴다. `gap`은 포화 키워드를 상위로 올리는 결함이 실측돼 판정에서 뺐다. 왜 지금 생겼는지(가결·공고·정부 발표·시즌·보도) 확인 못 하면 후보에서 뺀다.
- **cluster-auditor** — 비지역 클러스터의 과포화·의도 중복을 본다. **지역 글은 과포화 판정 대상이 아니다**(2026-09-09 판정 철회). 지역 후보는 `node scripts/build-cluster-intents.mjs --check "<지역>" <A|B|V> --facts=<초안 post.json>`(초안이 없으면 `--who=.. --amount=.. --deadline=..`)의 PASS/VETO/FIX로만 거른다. coreFacts를 안 넘기면 FIX 검사가 생략되고 reason에 "미제공"이 찍히니, 그 PASS를 FIX 아님으로 읽지 말고 초안을 넘겨 재실행한다. A가 있는 지자체에 V를 넣는 것도 VETO다. 보유 글 3건 이상 허브를 채우는 후보에 가점.
- 후보마다 **트랙·패밀리**를 붙인다. T1 = 지자체 민생·명절 지원금(지자체×패밀리 A/B/V, 롤업은 어휘 축×패밀리). T2 = 대형 세부 롱테일(실업급여·주휴수당·근로장려금·중위소득·에너지바우처·월세환급금). T3 = 선점 캘린더(9월은 0건).
- **갱신 후보**도 같이 낸다 — 날짜가 지난 글·사실이 바뀐 글(나주 9/30·10/16, 완주 10/30 같은 카운트다운)은 운영자 결정 ① 범위의 갱신 항목으로 보고에 싣는다.

인자로 키워드가 지정됐으면 이 단계는 건너뛴다.

### 3. SERP 실측 (naver-serp-scout spawn) — 건너뛰지 마라

후보를 **네이버에 실제로 검색**한다. 하루 예산은 T1 15 / T2 5 / 재측정 5(계획 §7 결정 7). 이력에 남기지 않는 정찰 모드를 쓴다.

```bash
node scripts/naver-rank-check.mjs --mode=scout --query="후보 쿼리"
# → {rank, webDocCount, aboveIsWholeBlock, openSlots, mainGovAbove, pressAbove, sisterAbove,
#    webDocOffset, verdictT1, verdictT2, above:[{host,kind,title,stale?}]}
```

판정은 **트랙별로 갈린다.**

- **T1 지역** — 검색량 문턱 **없음**. 조건은 둘: ① 공고·가결이 실제로 존재(go.kr 공고 URL 또는 언론 3곳 이상) ② `verdictT1: "open"`(위에 시군 본청 go.kr ≤1 · 언론 ≤3 · 자사 미노출 또는 4위 이하 — 자사가 이미 3위 이내면 closed). 접미형("X군 민생지원금") 1개 + 최다 변형 1개, 두 쿼리를 잰다. 군 단위는 접미형이 유입의 85~100%다.
- **T2 롱테일** — `keyword-volume` `recentRelative`(= 레이더 `signals.volume.recent7`) ≥ 1.5 **하나만** 문턱, 그다음 `verdictT2: "open"`(openSlots ≥2; 자매는 `sisterAbove`로 보고만, verdict를 닫지 않는다).
- `webDocOffset ≥ 30%`(웹문서 블록이 그만큼 아래) → 신규 금지. 15~30% → 경고로 보고.
- awoo가 이미 노출 중 → 신규 금지, **갱신 트랙**으로 옮긴다. 순위가 4위 이하로 떨어진 지역 쿼리는 **패밀리B 트리거**. `above[]`에 같은 제목 언론 3건 이상이면 "개시일 언론 신디케이션" 원인 코드를 따로 적는다(품질 문제가 아니다).
- `rank: null`은 `aboveIsWholeBlock`으로 구분한다 — 블록 전체가 위에 있는 것과 미노출은 다르다. null이 발행을 막지 않는다.
- 옛 규칙 폐기: "`webDocCount` 3 이하면 UGC 질의라 못 이긴다"는 **틀렸다**(web3 1위 78, web5 1위 1,746 실측). 얇은 블록은 오히려 진입 조건이다. "`externalCount: 0`이면 버린다"는 T2에서 `verdictT2`(openSlots)로 흡수됐다. T1은 본청·언론 카운트가 기준이라 외부 웹 수로 판단하지 않는다.
- 자매 호스트(`docs/ops/sister-sites.json`)가 위에 있으면 `sisterAbove`로 보고만 한다 — 민생 SERP 54건 중 자매 0이라 지연 사유가 아니다.

### 4. 운영자 보고 — 여기서 루프가 멈춘다 (운영자 결정 ③)

**이 명령의 마지막 자동 단계다.** 후보 표를 운영자에게 보고하고, **발행은 운영자가 확인해 지시할 때까지 하지 않는다.** 0400 자동 발행은 이 보고와 무관하게 매일 1건 그대로 돈다(운영자 결정 ②).

보고 표 열: **트랙 · 패밀리 · 타깃 쿼리(제목 선두) · 근거(신호·개시일·`--check` 판정·SERP 판정·webDocOffset) · 예상 유입/주 · 조건**(공고 URL·B키 2개·오프셋 등 발행 전 확인할 것). 갱신 후보(대상 글 경로·고칠 사실·날짜)도 같은 표 아래 붙인다. 같은 내용을 `docs/ops/DAILY-KEYWORDS.md`에도 남긴다(파이프라인 스크립트가 만들면 그것을 인용, 없으면 직접 쓴다).

인자로 키워드가 지정된 실행은 그 자체가 운영자 지시이므로 4단계를 지나 5단계로 간다.

## 운영자 지시 후 — 발행 단계

운영자가 후보 번호·쿼리를 지정하면 아래를 실행한다(`/post`·`/naver` 인자 실행과 같다).

### 5. 작성 (post-writer spawn)

- **제목은 타깃 쿼리를 그대로 맨 앞에.** 연도·의문형을 앞세우지 마라. 키워드 2회 이상 반복은 네이버 명시 불이익이니 1회만.
- **`targetQuery` 필드를 반드시 넣어라.** 이게 있어야 다음날 자동으로 순위 측정 대상이 된다. 없으면 이 루프가 끊긴다.
- **`contentVersion: 2`를 반드시 넣어라.** 독자 가독성 v2 렌더·린트 게이트다(`docs/ops/READER-UX-V2.md`). 출처는 `(출처: …)` 괄호가 아니라 문장 속 명사 링크 `[조문명](URL)`로. 기존 글에는 추가 금지.
- 1단계에서 받은 교정 규칙을 적용한다.
- **패밀리 템플릿**(A/B/V)에 맞춰 coreFacts `who`·`amount`·`deadline`을 채운다. 군은 "X군 민생지원금" 정확일치를 제목 선두에, 시는 변형 축(10만원 신청·날짜·2026·추석·도 접두)을 제목·본문에 전부. 사용자 언어 선두 + 공식명 병기(고창은 공식명만 써서 허브가 대신 2위였다).
- 품질 하한: 공고 고유 사실 2개 이상 · 1,500자 · 공고 출처 링크 · 14자 shingle ≤15%.
- 나머지는 `docs/ops/GOOGLE-NAVER-DUAL-STANDARD.md` 준수(구조 프로파일 로테이션·정보 이득 ≥2).

### 6. 검증 (병렬 spawn)

- **naver-content-shaper** — 네이버 공식 조건(제목·구조·출처·고유성·최신성)
- **fact-checker** — 수치·날짜·인용 귀속. 지역 글은 go.kr 공고 원문 대조, V형은 공고 부재를 직접 확인
- **google-quality-auditor** — 구조 지문·정보 이득

그다음 `npm run lint:content && npm run build`

### 7. 거부권 (publish-gatekeeper spawn)

**VETO면 점수와 무관하게 발행하지 않는다.** FIX면 신규 대신 기존 글 갱신(운영자 결정 ① 범위)으로 바꾼다. 대체 조치(패밀리B 신규 | 허브 표 행 | 기존 글 사실·날짜 갱신)를 대신 실행한다. 물결 창 안(개시 D-7~D+8)이면 속도 항목은 면제다. 수동 트랙 신규 0건은 실패가 아니다.

### 8. 발행

운영자에게 [제목 / 타깃 쿼리 / 트랙·패밀리 / SERP 판정 근거(webDocOffset 포함) / 검증 결과 / 1단계 교정 반영 내역]을 최종 확인받고 발행.

```bash
npm run sync:history && npm run indexnow:ping && npm run update:today
node scripts/build-cluster-intents.mjs --append <발행한 post.json 경로>
```

네이버 수집 요청(수동): https://searchadvisor.naver.com/console/site/request/crawl

### 9. 다음 회차로 넘길 것

`docs/ops/rank-targets.json`에 새 타깃을 넣을 필요는 없다 — 포스트의 `targetQuery`가 자동 편입된다. 지역 글은 접미형·변형 각 1개가 잡히도록 `targetQuery`를 접미형으로 둔다.
1단계에서 "버려라"로 판정된 쿼리는 `note`에 사유를 적어 남긴다. **지운 이유를 남겨야 같은 쿼리를 또 고르지 않는다.**
사후 측정은 발행 7·14·30일 + 지자체 개시일 D-1·D+1. 4위 이하 = 패밀리B 트리거.

## 금지

- 네이버 어뷰징 일절 금지 — 매크로·계정 대량 운영·링크 구매·클릭 조작. 네이버가 스팸으로 명문화했고 걸리면 도메인이 통째로 빠진다. 목적을 이루는 게 아니라 파괴한다.
- 기존 글 수정은 **운영자 결정(2026-09-10) 범위 안에서만** — 틀린 정보와 바뀐 날짜는 고친다(사실 정정·`updates[]`·`dateModified`·표 행). 제목·slug·구조·전면 재작성은 금지(노출 유지).
- 본문 변경 없이 `dateModified`만 올리기 금지(구글 공식 금지 항목).
- 이 루프가 스스로 발행하지 않는다. 후보 보고(4단계)까지가 자동이고, 발행은 운영자 지시 뒤다. 0400 자동 발행(`.github/workflows/auto-publish-0400.yml`)은 건드리지 않는다.
- C-Rank·D.I.A.를 근거로 판단하지 마라 — 네이버 블로그 랭킹 로직이고 외부 웹문서 적용 근거가 공식 문서에 없다.
- 순위가 안 나오면 색인 탓하지 마라. 색인은 당일 된다.
- **측정 표본이 적은데 규칙을 만들지 마라.** 관측 2회 이하는 "표본 부족"으로 남기고 넘어간다.
